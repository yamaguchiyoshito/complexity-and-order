# 動く図（GIF）の制作計画（未着手）

作成日: 2026-10-30
状態: 計画のみ。本文、図、スクリプトは変更していない。

## 1. 要件

- 矢印の上をリクエスト（トラフィック）が流れる。主役はトラフィック。
- 到着した箱がふわっと光る、アイコンが小さく跳ねる程度の反応を付ける。
- 文字は動かさない（位置も不透明度も固定）。
- 6秒で1周。最後のフレームから最初のフレームへ継ぎ目なくループする。
- 出力は GIF。
- 対象は、動かすことが効果的な図に限る。

## 2. 対象の選定

動かす価値があるのは、次の三つを満たす図に限る。

- 図の中に「送る側 → 矢印 → 受ける側」の流れがあり、流れる「もの」が本文で名指しされている。
- 流れの到着やタイミングが、その回の主張そのものである。
- 静止画では読者が想像で補っていた動きがある。

| 図 | 回 | 判定 | 理由 |
| --- | --- | --- | --- |
| 図22 コモンズ | 22 | **採用（パイロット）** | 五つのチームから共通基盤へリクエストが流れる構図そのもの。基盤が光り、混む様子が主張に直結する |
| 図18 頑健だが脆い | 18 | **採用** | 頻出の障害が厚い防御で吸収される流れと、6秒に一度だけ想定外が薄い防御を抜ける対比を、時間でしか見せられない |
| 図15 情報ボトルネック | 15 | **採用** | ログの項目が T を通って残るか落ちるかは、流れの途中で起きる。到着した右の箱が光る |
| 図13／図24 会話 | 13・24 | **採用（1本を両回で共用）** | 説明が A→B、再構成が B→A と往復する。到着した側の概念図が小さく跳ねる。第24回は同じ動きで「往復が続く」を見せる |
| 図2 開放系 | 2 | 見送り | 流れはあるが主張は定常状態で、静止で足りる |

| 図16 因果創発 | 16 | 見送り | 受け渡しの待ちは動かせるが、回の主眼は粒度の比較で、動きが主張を増やさない |

採用は4点（図22、図18、図15、図13／24共用）。パイロットは図22。

## 3. 動きの設計

### 3.1 共通

| 項目 | 値 |
| --- | --- |
| 周期 | 6.0秒 |
| フレーム | 10 fps、60枚（61枚目＝1枚目になるよう設計し、61枚目は出力しない） |
| トラフィック | 直径10pxの丸。送り元の色。既存の矢印の線上を等速で進む |
| 箱の反応 | 0.4秒。枠の色を背景へ薄く重ね、不透明度 0 → 0.35 → 0（イーズ） |
| アイコンの反応 | 0.3秒。3pxの上下の跳ね |
| 文字 | 全フレームで同一座標・同一不透明度 |
| 継ぎ目 | 周期を 6/k 秒（k は整数）か位相差で揃え、発光と跳ねは t=0 と t=6 でゼロ。粒子は6秒で整数回の移動 |

### 3.2 図ごと

**図22（コモンズ）**
- チームA〜Eから位相 0, 1.2, 2.4, 3.6, 4.8 秒でリクエストが出発し、1.5秒で基盤に着く。常に1〜2個が画面上にある。
- 到着のたびに基盤の円が光る（0.4秒）。
- 下段の四つの箱は、6秒に一度ずつ順に小さく跳ねる（1.5秒間隔）。利用・負担・監視・改訂の四つの経路が回っていることを示す。
- 「利用する」などの文字は動かさない。

**図18（頑健だが脆い）**
- 左・右・下の「頻出の障害」は2秒周期（位相 0, 0.67, 1.33 秒）で粒子が矢印上を進み、厚い防御に当たって光り、消える。
- 上の「想定外の外乱」は t=3.0 に一度だけ粒子が薄い線を通過して系の箱に届き、箱が0.6秒暗転して戻る。
- 6秒で頻出は9回、想定外は1回。頻度の差がそのまま見える。

**図15（情報ボトルネック）**
- 入力Xの8項目から0.3秒間隔で粒子が出て、上の T へ向かう。残る3項目は T を通過して右の箱へ着き、箱が光る。残り5項目は T の手前で消える。
- 3秒後に下の T について同じことが起こる。6秒で上下1回ずつ。
- 「ボトルネック T」などの文字は動かさない。

**図13／図24（会話）**
- 0.0〜2.4秒: 説明の粒子が A→B の矢印上を進み、到着で B の概念図が跳ねる。
- 3.0〜5.4秒: 再構成の粒子が B→A を進み、到着で A の概念図が跳ねる。
- 5.4〜6.0秒: 両方の概念図の枠が同時に薄く光る。第13回では「違いが見つかる」の瞬間、第24回では「往復が続く」の瞬間として同じ動きを使う。
- 1本の動きを両回の GIF に流用し、下の文字だけが違う。

## 4. 技術方式

- **フレーム生成**: Python が各フレームの静止 SVG を決定論的に生成する。`draw_figures.py` の描画関数を時刻 t 付きで呼べるよう拡張するか、`scripts/animate_figures.py` が同じ道具（`Figure` クラス）で描く。SMIL（`<animate>`）と JavaScript は使わない。現行の `validate.py` が禁止しているためと、GitHub 上の表示に依存しないためである。
- **ラスタ化**: 導入済みの `rsvg-convert`（librsvg）で PNG にする。日本語フォントの描画はパイロットで確認する。
- **GIF 化**: 導入済みの `ffmpeg` で `palettegen` と `paletteuse` の2パス。10 fps、`-loop 0`、幅 960px に縮小して容量を抑える。
- **出力先**: `assets/animations/NN-slug.gif`。`assets/` 配下だが `.gif` は `validate.py` の SVG 検査の対象外で、`build.py` は `assets/` を丸ごと複製する。フレームの SVG と PNG は一時領域に置き、リポジトリに入れない。
- **本文への置き方（要判断）**: 案1 は静止図の直後に「図22-動」として GIF を置く（GitHub でも動く）。案2 はサイトだけ `build.py` で差し替える。推奨は案1。`series.json` の `figures` 配列に登録し、`validate.py` の図参照検査を `.gif` にも通す小修正を入れる。
- **容量の見積り**: 960×544、60枚、64色で1点あたり 300〜800KB。4点で 2〜3MB。Pillow と Playwright は不要。

## 5. 検証

1. フレーム0と「フレーム60」の SVG 文字列が同一であること（継ぎ目の保証）。
2. 全フレームで `<text>` 要素の座標と属性が同一であること（文字の静止の保証）。
3. `ffprobe` で GIF のフレーム数 60、長さ 6.0 秒、ループ指定を確認。
4. ブラウザで実再生し、主役のトラフィックが目立つこと、反応が控えめであること、文字が読めることを目視。
5. `validate.py` → unittest → `build.py` → `check_html.py`。

## 6. 手順

1. `scripts/animate_figures.py` の骨組み（時刻 t を受ける描画、フレーム出力、rsvg-convert と ffmpeg の呼び出し、同一性の検査）と、図22 のパイロットを作り、GIF をレビューに出す。
2. 承認後、図18、図15、図13／24 を作る。
3. 本文への配置、`series.json`、`validate.py` の小修正、`guides/EDITING.md` への手順追記、CHANGELOG 2.1.0。
4. push と Pages 再公開。

## 7. 決めてほしいこと

1. 対象を上の4点（図13／24は共用）でよいか。
2. GIF を本文に置く（案1）か、サイトだけ（案2）か。
